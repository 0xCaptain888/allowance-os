# Android release process

Every installable Allowance OS iteration must remain downloadable and independently checkable after temporary GitHub Actions artifacts expire. Production and test signing identities are deliberately separated.

## Required version changes

Before release:

1. update `versionCode` and `versionName` in `mobile/android/app/build.gradle`;
2. add a dated section to `CHANGELOG.md` and a release note in `docs/releases/`;
3. update `evidence/android-build.json` after the final local build;
4. run TypeScript, Android, and Rust checks as appropriate;
5. commit and push `main`;
6. choose either the production or test tag described below.

The Android header reads `BuildConfig.VERSION_NAME`; it must not contain a separately hardcoded version.

## Production release: `android-vX.Y.Z`

`.github/workflows/android-release.yml` is the production-only path. The `android-production` GitHub Environment must contain:

- `ALLOWANCE_OS_KEYSTORE_BASE64`;
- `ALLOWANCE_OS_STORE_PASSWORD`;
- `ALLOWANCE_OS_KEY_ALIAS`;
- `ALLOWANCE_OS_KEY_PASSWORD`.

The workflow validates the tag, restores the protected keystore, runs unit tests, builds `assembleRelease`, verifies the APK certificate with `apksigner`, generates `SHA256SUMS.txt`, and creates the GitHub Release. Missing signing configuration fails the workflow; it never falls back to a debug certificate.

```bash
git tag -a android-v0.11.1 -m "Allowance OS Android v0.11.1"
git push origin android-v0.11.1
```

Do not create this tag until the protected signing environment is configured and its recovery backup has been tested.

## Debug QA release: `android-test-vX.Y.Z`

`.github/workflows/android-test-release.yml` builds a debug-signed APK for device QA, hackathon judging, or reproducibility. Its title and notes explicitly say that it is not a production or dApp Store release.

```bash
git tag -a android-test-v0.11.1 -m "Allowance OS Android test build v0.11.1"
git push origin android-test-v0.11.1
```

Debug certificates differ by build environment. The attached checksum verifies the downloaded bytes, but does not establish a stable production publisher identity.

## Local production build

The repository provides a fail-closed local path:

```bash
ALLOWANCE_OS_STORE_FILE=/absolute/path/to/allowance-os-dappstore.jks \
ALLOWANCE_OS_STORE_PASSWORD='set-locally' \
ALLOWANCE_OS_KEY_ALIAS=allowance-os-dappstore \
ALLOWANCE_OS_KEY_PASSWORD='set-locally' \
npm run android:release
```

`android:release` runs Android tests, discovers the versioned release APK generated by Gradle, and writes `SHA256SUMS.txt`. Never commit the keystore or any password.
